# weread-organizer

## 默认模式：计划，不直接写远端

官方微信读书 Skill 当前公开文档明确支持读取和管理书架相关信息，但具体可安全调用的写接口应以**当前版本能力文档和 `/_list`** 为准，不能凭社区项目或旧接口猜测。

因此本项目的默认实现是：

```text
事实层 → 整理计划 → 人工审核 → （可选、另行确认的远端执行）
```

而不是“AI 判断完就直接搬书”。

## 生成整理计划

先生成统一事实层：

```bash
python scripts/build_visualization_context.py
```

然后：

```bash
python scripts/plan_shelf_organization.py --strategy hybrid
```

支持：

- `status`：深读 / 已读 / 在读 / 待读
- `category`：按微信读书分类的一级分类整理
- `hybrid`：状态 × 分类

输出：

```text
data/analysis/shelf_plan.json
data/analysis/shelf_plan.md
```

这两个文件都是**本地预览**，字段 `remoteMutationPerformed` 固定为 `false`。

## 状态规则

- `深读`：有自己的想法，或笔记总数达到较高阈值；
- `已读`：进度 100%，且不满足深读优先规则；
- `在读`：0 < 进度 < 100%；
- `待读`：没有明确进度和深度笔记证据。

这些标签是整理用途，不代表阅读质量判断。

## 真正执行远端整理前

只有用户明确说“按这个计划执行”，并且当前官方微信读书 Skill 文档 / `/_list` 明确存在对应写接口时，才进入执行流程：

1. 再读取一次最新书架，防止计划过期；
2. 展示将变更的分组和书籍数量；
3. 只对白名单中的目标分组执行；
4. 每批写入后重新同步验证；
5. 对任何不确定、已变化或失败的书停止操作；
6. 不删除用户已有分组，除非用户明确要求。

如果当前官方接口只支持读取，就停留在 plan-only，不使用未文档化接口冒险写入。

## 本地书单

`shelf_plan.md` 本身就是可分享的本地书单视图。也可以从其中抽取：

- 本月待读
- 当前在读
- 深读复盘
- 某一分类专题书单

本地书单不等于修改微信读书远端 archive / 书单。
