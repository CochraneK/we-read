# weread-recall

## 核心原则

Recall 的目标不是让用户背原句，而是检测“是否还能重新解释、举例、应用和质疑”。

必须区分：

- `mark`：用户曾关注的原文，不自动代表认同
- `review`：用户自己曾写下的想法，更适合做“观点是否变化”的回顾

## 先建立确定性队列

```bash
python scripts/build_visualization_context.py
python scripts/build_recall_queue.py
```

默认规则：

- 只选至少 30 天前的证据
- 更久未回顾的优先
- 同样久时，个人想法 `review` 优先于普通划线 `mark`
- 每本书最多 2 条，避免单书淹没队列
- 私密范围完全继承 `visualization_context.json`

可调整：

```bash
python scripts/build_recall_queue.py --min-age-days 90 --limit 10 --max-per-book 1
```

## 可视化回顾卡

```bash
python scripts/renderers/recall.py
```

输出：

```text
data/analysis/reading_recall.html
```

卡片必须先显示问题，原始证据放在可展开区域。不要默认把答案直接露出来。

## 对话模式

### recall

针对划线：

- 用自己的话解释
- 举一个自己的例子
- 说明它成立的边界

针对想法：

- 当时为什么这么想
- 现在是否还认同
- 哪些后续阅读可能改变了这个观点

### feynman

要求用户像给没读过这本书的人解释一样回答。

流程：

1. 只给问题，不先给原文
2. 用户回答
3. 再展示原始证据
4. 对比“遗漏 / 混淆 / 新增理解”
5. 必要时再用 `weread-search` 搜其他书的相关证据

### contrast

优先选来自不同书、主题可能相近但观点不同的证据，要求用户解释冲突或差异。

如果当前队列不包含足够的跨书材料，先用 `weread-search` 搜索，不得虚构对立观点。

## 出题规则

1. 不要问只能靠记住原句才能回答的问题。
2. 不要把作者观点写成用户观点。
3. 用户回答后，评价应围绕原始证据，不围绕“标准答案措辞”。
4. 模型可以指出遗漏和潜在矛盾，但不能伪造书中内容。
5. 如果证据本身只是断句或上下文不足，应降低问题难度，或跳过。
6. `review` 可以问“现在是否还认同”；`mark` 不应问“你为什么相信这句话”，除非另有用户想法作为证据。
7. 回顾结束后可以总结“哪些内容记得牢 / 哪些需要重看”，但不要据此做人格诊断。

## 与其他 Skill 联动

- `weread-search`：找相关旧证据
- `weread-visualization`：把长期回顾结果汇入报告或认知变迁
- `huashu-weread` alchemy：把回顾后仍有价值的材料整理成主题笔记

## 不做什么

- 不自动把所有旧划线都做成卡片
- 不按划线数量判断知识掌握程度
- 不把“忘了”解释为认知能力问题
- 不为了题目完整性生成不存在的引用
